# EditSave — редактор сохранений GTA2

Кроссплатформенное Qt-приложение на C++17 для правки игровых сохранений
GTA2 (`plyslotN.svg` и `plyslotN.dat`).

Все смещения взяты из декомпиляции retail-кода в `dump/IDA/gta2.exe.c`,
а не подобраны перебором.

## Сборка

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

Нужна Qt (5 или 6) с компонентами `Core`, `Gui`, `Widgets`. CMake сам
находит Qt через `find_package(QT NAMES Qt6 Qt5 ...)`.

### Windows

```powershell
$env:Path = "D:\Qt\Qt5.14.2\Tools\mingw730_64\bin;D:\Qt\Qt5.14.2\5.14.2\mingw73_64\bin;$env:Path"
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
```

## Что куда попадает

Всё собирается в `bin/` этого каталога:

| файл | что |
|---|---|
| `EditSave.exe` | GUI-редактор |
| `EditSaveCli.exe` | консольная проверка парсера |
| `Qt5Core/Gui/Widgets/Svg.dll` | библиотеки Qt |
| `platforms/qwindows.dll` | плагин оконной платформы (обязателен) |
| `styles/`, `imageformats/` | плагины стилей и форматов |
| `libgcc_s_seh-1.dll`, `libstdc++-6.dll`, `libwinpthread-1.dll` | рантайм MinGW |

Таргет `deploy` вызывает `windeployqt`; `stage` зависит от него, поэтому
`cmake --build build` уже даёт готовый к запуску каталог. На macOS/Linux
`deploy` копирует бинарник (и libs на Linux) рядом — там зависимости
системные.

## Проверка без GUI

```bash
bin/EditSaveCli.exe --dir C:/work/log/player --slot 0
```

Печатает разобранный сейв и делает **побайтовую проверку round-trip**:
перезаписывает файл во временный и сравнивает с оригиналом. Если формат
handling сломан — выводится `FAIL round trip` и ненулевой код возврата.
Это важно: сломанный парсер в GUI выглядит точно так же, как рабочий.

## Формат файлов

### `plyslotN.svg`

```
[ block0 : 1864 B ][ u32 len1 ][ data1 ][ u32 len2 ][ data2 ][ u32 len3 ][ data3 ]
```

`block0` собирает `MissionManager::sub_475CA0`, пишет `MissionManager::SaveFile`.
Три хвостовых блока даёт `MapRelatedStruct::sub_4642A0` — они **побайтово
одинаковы во всех сейвах**, то есть это константы карты, а не состояние игрока.

Ключевые поля block0:

| смещение | размер | что |
|---|---|---|
| `0x00` | 25 | имя карты, `data\wil.gmp` |
| `0x19` | 25 | имя стиля, `data\wil.sty` |
| `0x32` | 25 | имя скрипта, `data\wil.scr` |
| `0x4B` | 1 | город |
| `0x4C` | 1 | уровень, `city<<4 \| sub`, `0xFF` = нет |
| `0x4D` | 1 | банда |
| `0x64` | 4 | **деньги** |
| `0x6C` | 2 | здоровье |
| `0x6E..0x8E` | 2×17 | бонусы |
| `0x90..0xB7` | 4×10 | `field644`, назначение неизвестно |
| `0xBA..0xC8` | 1×15 | патроны |
| `0xC9..0xD2` | 1×10 | уважение бандам |
| `0xD4` | 1 | жизни |
| `0xE0` | 2 | уровень розыска |
| `0x744` | 4 | токены |

### `plyslotN.dat`

18 байт заголовка + **12 записей по 9 байт** `{ u8 flag; u32 best; u32 last }`.
Геометрия подтверждена `PlayerData::WriteFileNamePlayer` (`a3 = 126`).
Индекс записи кодирует место: `arena = idx/4`, `sub = idx%4`.

`best` / `last` — **снимки денег**, а не счёт: их пишет
`PlayerData::sub_4A8F90` из `GetMoneyPlayer`.

## Чего редактор НЕ позволяет

Это не ограничение UI, а вывод реверса.

**`0x710..0x741` — трогать нельзя.** Загрузчик `MissionManager::sub_47F0B0`
делает `qmemcpy` этих 48 байт в **живую** `gObject->S63`, где лежат
указатели. Запись мусора сюда роняет игру при первом обращении — это была
причина обоих крашей при первой попытке.

**`0x12C` / `0x130` — маски, они завязаны на RAM.** Биты индексируют массивы
`arr2_15` (32 ID) и `arr_12` (25 ID), которые **не сохраняются**. Бит без
соответствующего ID даёт разыменование мусора в `StartMission`. В
интерфейсе эти поля помечены как опасные и заблокированы по умолчанию.

**Таблица миссий `0x134..0x5E3` — производная от карты.** `sub_47EE70`
при каждом сохранении заново обходит 6000 слотов скрипта и пересобирает
таблицу, оставляя только маркеры типов 275/276. Поэтому диапазон ID
различается по картам (wil начинается с 414, bil — с 67), но одинаков для
всех слотов одной карты. Правка бессмысленна — игра перезапишет. Вкладка
сделана read-only.

**`0xE2..0x127` — инертная зона.** Ни один известный writer её не пишет, а
сравнение двух реальных сейвов разных городов показало 0 отличающихся байт.

Практический вывод: **пяти «списков миссий» в сейве нет**. Списки миссий
банд, дополнительной работы и т.п. игра вычисляет в RAM из данных карты и
скрипта при загрузке. Персистентно сохраняются только деньги, уважение
бандам, бонусы, патроны, жизни и розыск — их редактор и даёт менять.

## Безопасность

Запись всегда идёт через `Backup now` в `<saveDir>/../exp` с меткой времени.
`Reload from disk` отменяет несохранённые правки. При выходе с
несохранёнными правками спрашивает подтверждение.

## Создание сохранения

Кнопка **New save...** собирает новую пару `plyslotN.svg` + `plyslotN.dat`
в выбранном слоте.

* `block0` (1864 Б) строится с нуля: имена карты/стиля/скрипта, arena,
  бонус, банда, деньги, здоровье, жизни, 15 счётчиков патронов, 10 уровней
  уважения, патроны и powerup обнуляются.
* Три хвостовых блока (1356 Б суммарно) — это константы карты, а не данные
  игрока: первые два совпадали байт-в-байт у всех сравненных сейвов wil,
  а `MapRelatedStruct::sub_4642A0` пересобирает их из `.gmp`. Полный
  генератор не восстановлен, поэтому они копируются из **шаблона** — любого
  существующего сейва. Если шаблон недоступен, создание отказывается с
  понятной ошибкой, а не пишет битый файл.
* `.dat` создаётся пустым: 18 Б заголовка и 12 записей по 9 Б, все флаги
  прогресса = 0 (ни одна локация не открыта).
* Занятый слот резервируется автоматически, перед перезаписью показывается
  подтверждение, а копия с меткой времени создаётся заранее.

## Смена города

Селектор **City:** в верхней панели (нумерация для пользователя 1/2/3, в
файле хранится arena 0/1/2).

| Город | arena | файлы |
|---|---|---|
| Liberty City | 0 | `data\wil.gmp`, `data\wil.sty`, `data\wil.scr` |
| Industrial City | 1 | `data\ste.gmp`, `data\ste.sty`, `data\ste.scr` |
| Bilboa City | 2 | `data\bil.gmp`, `data\bil.sty`, `data\bil.scr` |

Одним действием переписываются три имени, байт arena, счётчик `0x12A` и все
300 строк таблицы `0x134..0x5E3` — ровно так же, как это делает
`MissionManager::sub_47EE70`. Путь к папке с файлами игры задаётся в
**Settings → Game data**; если `.scr` не найден или не соответствует
выбранному городу, изменение отклоняется целиком.

Проверка воспроизводимости:

```bash
bin/EditSaveCli.exe --dir C:/work/log/save --slot 5 --check-city
```

Для настоящего сейва `bil.scr` скрипт сообщает `all 107 ids identical`.
Единственное расхождение — значение `state` у ID 160, которое игра пишет в
момент сохранения; ID при этом совпадают, а именно они и определяют карту.

## Оружие и бонусы

Вкладка **Weapons** показывает 15 слотов с настоящими именами из
`gta2/Game/Weapon/Weapon.h` и 17 бонусов из `gta2/Game/PowerUp/PowerUp.h`.

Порядок слотов выведен из кода, а не взят из старого редактора:
`Player::sub_4A5B40` создаёт `sWeapon[0..14]` для `Index < CAR_BOMB` (15),
поэтому 15 байт патронов `0xBA..0xC8` соответствуют `WeaponType` 0..14
именно в этом порядке. Нумерация старого `GTA2-SaveEdit` в нескольких
местах с этим не совпадает, поэтому источником служит восстановленный enum.

Powerup читаются как **17 отдельных байт `0x6E..0x7E`**
(`Player::sub_4A5A50` читает `a2+26` и 17 байт), а не как 17 слов. Старый
справочник указывал редкие смещения (`0x7B`, `0x81`, `0x85`) — это неверно.

## Языки

Исходный язык — английский (строки `tr()` в C++). Русский грузится из
`bin/translations/editsave_ru.qm`; переключатель в **Settings → Language**.

`.ts` файлы **генерируются** из исходников, а не правятся руками:

```bash
python tools/make_translations.py
```

Скрипт вытаскивает `tr()`, `translate("Ctx", ...)` и
`QT_TRANSLATE_NOOP("Ctx", ...)` из всех `src/*.cpp`, собирает русские
переводы из словаря `RU` и пишет `translations/editsave_{en,ru}.ts`.
Новая пользовательская строка автоматически попадёт в отчёт как
непереведённая, а не пропадёт молча. В `CMakeLists.txt` при наличии
`Qt LinguistTools` из `.ts` собираются `.qm` и копируются в
`bin/translations/`; если `lrelease` недоступен, сборка продолжается с
предупреждением и приложение работает по-английски.

Qt не перевызывает `tr()` у уже созданных виджетов, поэтому смена языка
пересоздаёт окно (папка, слот и масштаб сохраняются).

Проверка перевода без запуска GUI:

```bash
bin/EditSaveCli.exe --dir C:/work/log/player --slot 0 --lang ru
```

## Что изменено в этом проходе

* `src/ScriptFile.*` — разбор главного `.scr` (12000 × u16 заголовок +
  65536 Б скрипта), выборка маркеров 275/276.
* `src/Cities.*` — таблица городов и поиск по имени файла.
* `src/SaveFile.*` — `createNew()`, `applyCity()`, `applyCityNames()`.
* `src/WeaponTable.*` — вкладка оружия и бонусов.
* `src/Translator.*` — загрузка `.qm` и переключение языка.
* `src/FieldDefs.*` — контекст перевода исправлен на `FieldDefs`
  (`QObject::tr` с табличным аргументом не переводился в принципе).
* `src/cli_main.cpp` — `--check-city`, `--new <arena>`, `--lang`,
  вывод UTF-8 принудительно.
* `tools/make_translations.py` — генератор `.ts`.
